# Minimum patch proposal — design only, NOT applied or tested as a fix

1. **Explicit fatal worker response and exit.** In chatterbox_worker.main, distinguish invalid-input/nonfatal errors from explicitly recognized sticky CUDA failures (device-side assertion, illegal memory access) and OOM. For fatal cases set state=error, send/flush a structured `{ok:false,state:error,fatal_error:true,error_type,operation,request_id,error}` response, then exit the worker without calling move_model/deactivate/synchronize/seed/generate on the poisoned context. OOM should have an explicit policy; current code already marks error and forbids retry. Do not classify every RuntimeError or every mention of CUDA as fatal. No automatic resynthesis or seed retry; failed caller still receives its failure.

2. **Adapter remembers errors and offers bounded worker-only retirement.** Store the entire failed response in `last` on synth failure. Fatal flag must survive in health. Add fatal retirement that does not send cooperative CUDA shutdown RPC: terminate only the owned child, wait with deadline, kill only that child if necessary, wait again. Reuse CPU-start routine for replacement, with bounded spawn/startup detection and EOF handling. On RPC timeout/protocol ambiguity retire that generation before reusing the pipe; stale uncorrelated replies must not be mistaken for a new operation. Existing `terminate` calls shutdown for up to 20 seconds first and startup `_wait_event` uses blocking readline despite a nominal 900-second deadline; do not call those paths "bounded" without fixing them.

3. **One lifecycle lock shared by queue, idle and close.** Create an RLock before threads start. Queue holds it from active_job publication through activation, request callback, error recovery and final active_job clearing. Idle takes the same lock before checking active_profile, health, busy/queue/idleness and through its entire offload/recovery transaction; recheck all conditions under lock. Idle must never retire/restart while a job is using the worker. `_activate`, recovery and close use this lock (RLock for nested helper calls). Protect snapshot/event state reads coherently or expose cached snapshots; avoid issuing slow RPC while an unrelated lock is held. Preserve stop_lock order consistently to avoid deadlock. A serial queue thread alone does not serialize a separate idle thread.

4. **Recover the failing OWNER, not merely requested profile.** Catch old-profile deactivation inside the transition handler. If old owner is fatal, dead, or cannot be safely offloaded, retire its owned process under lifecycle lock and confirm exit before clearing active_profile or activating another GPU owner. Never clear ownership just because an error was caught. Recovery success restores CPU-ready worker state/transition/state; failed confirmed retirement leaves explicit degraded/recovery_failed state and blocks activation safely. Replacement startup failure should not falsely claim recovered. Enforce finite recovery attempts/backoff, no loop of restart+resubmit. A same-profile fast return requires alive AND gpu_ready AND no fatal flag, not only name equality. Catch idle health/recovery exceptions and retain the idle loop.

5. **Retain diagnostics without changing synthesis behavior.** Replace DEVNULL with a bounded rotating per-worker stderr log (or pipe with continuous draining) and include path, worker generation/PID, request/chunk/seed, normalized-input length and hash, operation and first failure type in structured diagnostics. Do not log private raw text by default or mix diagnostics into stdout JSON protocol. Optional CPU-side pre-CUDA token/index range guards should record actual observed min/max and expected bounds, and reject invalid input only when those real invariants are known. Do not invent token vocabulary limits or add CUDA calls after the first fatal error. No voice/temperature/guidance/reference changes.

Required follow-up tests: positive cross-profile recovery after fatal synth; fatal exit exactly once; alive/error recovery; same-profile repaired activation; idle never overlaps dispatch or restart; bounded retirement failure preserves ownership; no silent replay; shutdown ordering; EOF/startup deadline and late-response isolation; nonfatal input failures do not restart workers. Current characterization/RED suite is evidence of defects, not validation of this unapplied design.
